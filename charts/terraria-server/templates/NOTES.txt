{{- if .Values.terraria.waitForWorld }}

The server is waiting for a world file (terraria.waitForWorld=true). Import yours with:

  kubectl cp ./MyWorld.wld {{ .Release.Namespace }}/$(kubectl get pod -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/name={{ include "terraria-server.name" . }} -o jsonpath='{.items[0].metadata.name}'):/terraria/.local/share/Terraria/Worlds/{{ .Values.terraria.world }}

The server starts as soon as the copy finishes. The world is on the persistent volume, so
later restarts load it directly even with waitForWorld left on.
{{- else if .Values.terraria.autocreate }}

A {{ if eq (int .Values.terraria.autocreate) 1 }}small{{ else if eq (int .Values.terraria.autocreate) 2 }}medium{{ else }}large{{ end }} world is generated on first start if none exists. To import an existing
world instead, install with terraria.waitForWorld=true and follow the printed kubectl cp command.
{{- end }}

Reach the server:
{{- if eq .Values.service.type "LoadBalancer" }}
  kubectl get svc -n {{ .Release.Namespace }} {{ $fullname }} -w   # wait for EXTERNAL-IP, connect on port {{ .Values.service.port }}
{{- else if eq .Values.service.type "NodePort" }}
  kubectl get svc -n {{ .Release.Namespace }} {{ $fullname }}      # connect to any node IP on the NodePort
{{- else if .Values.ingress.traefik.enabled }}
  via the Traefik TCP entrypoint "{{ .Values.ingress.traefik.entryPoint }}"
{{- else }}
  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ $fullname }} {{ .Values.service.port }}:{{ .Values.service.port }}
{{- end }}

Logs:
  kubectl logs -n {{ .Release.Namespace }} deploy/{{ $fullname }} -f
